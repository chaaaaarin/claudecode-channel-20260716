## 1. Fable 5で何が変わったのか

Claude Fable 5は、Anthropicが「長時間・複雑な推論とエージェント作業向けに作った、広く一般提供されている中で最も高性能なモデル」と位置づける2026年6月9日リリースのモデル。✅（Anthropic公式）1Mトークンのコンテキストウィンドウと最大128kトークンの出力に対応し、adaptive thinking（思考の深さを自動調整する仕組み）が常時オンで、`thinking: disabled`は使えない。✅

料金は100万トークンあたり、入力$10／出力$50。✅（公式Pricingページ）これはOpus 4.8（入力$5／出力$25）のちょうど2倍。プロンプトキャッシュは書込1.25倍〜2倍、キャッシュ読み取りは引き続き基本料金の10%（10倍引き）で変わらない。✅ 新型トークナイザーの採用により、同じテキストでも旧モデル比で約30%多くトークン化される点も見落としやすい。✅（公式ドキュメント）

新機能として、危険なリクエストを拒否できる**safety classifier**が搭載された。拒否時はエラーではなく`stop_reason: "refusal"`としてHTTP 200で返り、出力が生成される前の拒否には課金されない。✅（公式ドキュメント）

ベンチマークでは、SWE-Bench Pro 80.3%（次点+11pt）、空間推論（Blueprint-Bench 2）38.6%（Opus 4.8の14.5%からほぼ3倍）、法律推論（Legal Agent Benchmark）13.3%など、主要な指標でOpus 4.8・GPT 5.5・Gemini 3.1 Proを上回る。✅（Anthropic公式ベンチマーク表。全項目の比較表は[スライド資料](https://chaaaaarin.github.io/claudecode-channel-20260716/slides.html)を参照）

※ Cybersecurity・Biology 等、星印（*）の項目はセーフティ由来のブロックにより、Fable 5とMythos 5のスコアに差が出やすい区分（公式注記）。✅

## 2. なぜ今なのか（Before/After）

Fable 5の経緯は、単なる「値上げ」や「期間限定キャンペーン」では説明できない。実際には安全性インシデントを挟んだ一進一退の展開になっている。

### Before：無償提供 → 突然の全面停止

6月9日〜22日、Pro/Max/Team/Enterpriseプランでは追加料金なしでFable 5にアクセスできた。✅ ところが6月12日、Amazonの研究者が「小説内の対話」という体裁でモデルを騙すジェイルブレイク手法を用い、悪用可能なコードを生成させることに成功したと報告。🔶（複数の解説動画が同時期に言及）これを受け米国政府がFable 5・Mythos 5に輸出管理を適用し、Anthropicは「ユーザーの国籍をリアルタイムで検証する信頼できる方法がなかった」ため、**全ユーザーへのアクセスを一時停止**した。✅（Anthropic公式声明）

### After：7月1日に復旧、その後も無償期間を繰り返し延長

Anthropicは改善版の安全性分類器を開発し、報告された手法を「99%超のケースでブロック」できるようにしたうえで、6月30日に輸出管理が解除され、7月1日にグローバルアクセスが復旧した。✅ 復旧後は埋め合わせのように、無償アクセス＋Claude Code週間利用上限50%増という特典が繰り返し延長されている。当初7月7日までだった特典は、7月12日→7月19日23:59:59（米太平洋時間）と2度延長された。🔶（複数の解説動画・記事が同時期に報告）

さらに7月16日（本記事執筆時点）には、Anthropic公式アカウント（@ClaudeDevs）が「すべてのユーザーの5時間および週間のレート制限をリセットした」と発表している。✅（本人アカウントの投稿。投稿画像は[スライド資料](https://chaaaaarin.github.io/claudecode-channel-20260716/slides.html)に掲載）

一度止まった信頼を取り戻すための特典延長が続いている今が、使い方を固める実質的な最後のチャンスと言える。本格的な従量課金に戻ったとき、$10/$50という料金は無視できない金額になる。

⚠️ 注意: 同時期に確認した一部記事（claudefa.st等）は6月12日〜7月1日の停止期間中に書かれたスナップショットで、「Fable 5は誰も使えない」という記述が残っている。現在はAnthropic公式の復旧声明のとおり7月1日にグローバル復旧済みのため、この種の古い記事の停止情報は現状と矛盾する＝無効として扱う。

## 3. 仕組み・根拠：料金体系とEffort

節約を考えるうえで最初に理解すべきなのが、Fable 5・Mythos 5で唯一かつ最重要のコスト・速度コントロールである**effortパラメータ**。✅（公式ドキュメント）

| Effort | 概要 | 想定する使いどころ |
|---|---|---|
| max | 制約なしの最大性能 | 最も深い推論・最も徹底した分析が要る場面 |
| xhigh（Extra High） | 長時間のエージェント作業向け拡張性能 | 30分超の長時間コーディング・エージェントタスク、数百万トークン規模の予算 |
| high（デフォルト） | 高い性能。パラメータ省略時と同じ | 複雑な推論・難しいコーディング・多くのタスクで最適 ✅ |
| medium | バランス型。中程度のトークン節約 | 定型作業・ルーティンワーク |
| low | 最も効率的。速度・コスト最優先 | サブエージェントなど、単純作業 |

公式ガイダンスでは「**まずhigh（デフォルト）から始め、能力が最重要な作業だけxhigh、ルーティン作業はmedium/lowへ**」という順で調整することを推奨している。✅ 重要なのは、**Fable 5の低いeffort設定は、しばしば旧モデルのxhigh相当を上回る**という点。✅（公式ドキュメント）Effortを1段階上げるとコストはおおむね1.5倍になる。🔶（実演動画での体感値）

プロンプトキャッシュの割引率自体はOpus 4.8など他モデルと変わらず、キャッシュ読み取りは基本入力単価の10%（Fable 5なら$1/M）。✅（公式Pricingページ）Batch APIは入出力とも半額（$5/$25）で、即時応答が不要な処理はここに回すだけでコストが半分になる。✅

**注意：「Ultracode」はEffortの6段階目ではない。** Claude Codeの`/effort`メニューには上記5段階に加えて「Ultracode」という選択肢も表示されるが、これはモデルのEffortレベルではなく**Claude Code固有のセッション限定設定**。✅（公式ドキュメント）実体は「xhighエフォート」に「Claudeが承認なしにマルチエージェント（サブエージェント）のワークフローを自律的に起動できる常時許可」を組み合わせたもので、セッション限定（次回起動時は自動的に元の設定に戻る）。✅ xhigh自体が数百万トークン規模の長時間タスク向け最重量級ティアな上、この常時許可で複数エージェントが並行起動しうるため、簡単な作業でオンのままにするとトークン消費が急増しやすい。🔶（公式コストページでは、類似の複数インスタンス機能「Agent teams」が通常セッションの約7倍のトークンを消費すると明記されている。Ultracode内部の仕組みと完全に同一かは未確認）

## 4. 節約テクニック①：Effortの使い分け

3章の表をタスクに当てはめる際の判断基準:

- 通常のチャット・下書き・要約 → **low〜medium**で十分なことが多い
- 通常の開発作業・エージェントタスク → **high（デフォルト）**が既定の最適解
- 長時間の自律実行・複数ファイルにまたがる改修 → **xhigh**
- 「絶対に間違えられない」判断が必要な場面のみ → **max**

公式ドキュメントでは「Fable 5の低いEffort設定は、旧世代モデルのxhigh相当の性能をしばしば上回る」と明言されている。✅（Anthropic公式Effortドキュメント）つまりEffortを下げる判断は単なる妥協ではなく、Fable 5自体の地力の高さを踏まえた合理的な選択になる。

Claude Codeのデスクトップ/Webアプリでは、モデル選択画面の右下から個数（エフォート）を切り替えられる。Opus系モデルを使う場合は「思考」トグルがオフだと推論自体が働かないため、オンになっているか確認しておきたい。🔶

## 5. 節約テクニック②：バーベル戦略・オーケストレーション

一言でまとめると**「計画は賢いモデル、実行は安いモデル」**。Anthropicは公式に「作業は速くて安いモデルに任せて、重要な決断や計画のときだけ賢いモデルに任せる」という役割分担を推奨している。✅ Claude Sonnet 5とFable 5を掛け合わせてオーケストレーションすると、**Fable 5単体でやる場合と比べて92%の品質を63%のコストで実現できる**という実測結果を公式が示している。🔶（Anthropic公式解説を紹介した動画より）

同じ考え方を「10-80-10フレームワーク」（バーベル戦略）として整理している解説もある: 最初の10%（設計・アーキテクチャ）だけFable 5にやらせ、中間の80%（実装・テスト生成）はSonnet系やHaiku系に渡し、最後の10%（要件との整合性チェック）だけFable 5に戻す。🔶 この方法で35〜60%のコスト削減が報告されている。🔶

Claude Codeでの実践方法は2通りある。

- **`/advisor`コマンド**（ターミナル限定）: `/advisor`と打つとアドバイザーモデルを選択できる。アドバイザーには自分より賢いモデルしか設定できない。ただし**デスクトップアプリからは反応しないという落とし穴がある**。🔶（解説動画で報告）
- **プロンプト指示**（デスクトップ/Webアプリでも可）: 「設計・計画のサブエージェントはFable 5、実装は別モデルにして」と明示的に指示するだけで、同じ役割分担を再現できる。🔶

実演では、まずメインモデルをOpus 4.8やSonnet 5に設定した状態で「ハローワールドの実装計画を、Fable 5の計画エージェントを使って立ててください」のように**計画エージェントの担当モデルを名指し**し、その計画を受け取ったあとに「実装してください」と続けると、指定したモデルが実装を担当する、という流れが確認できている。🔶（実演動画）ただし`/advisor`機能はまだ不安定で、起動に失敗することがある。🔶

## 6. 節約テクニック③：トークン圧縮ツール

Claude Codeのシェル出力・会話コンテキストを圧縮する専用ツールも複数登場している。🔶（Elcamy Tech Blogの実測比較）

| ツール | 圧縮対象 | 削減率（実測） |
|---|---|---|
| rtk（Rust Token Killer） | シェル出力（git diff・grepなど） | 中央値約80%、巨大差分では99.5% |
| headroom | 会話コンテキスト全体 | 93.1%（30.9万→2.1万トークン） |
| lean-ctx | ファイル読み込み・シェル出力 | コード見出し抽出で96%、再読込キャッシュ99.9% |
| h5i | コマンド出力＋git連携 | 99.8%（完全可逆・原本をgitに永続保管） |

記事の結論は「まずrtkを導入し、それでも足りなければheadroomを追加する」という順番。🔶 lean-ctxは情報保全を優先する設計のため、git diffはほぼ無圧縮になる点に注意。🔶

もう一つ、発想の異なる裏技も報告されている。Claudeの画像トークンコストは**画像内のテキスト量ではなくピクセルサイズで固定される**という性質を利用し、大量のコンテキスト（システムプロンプト・JSON・ツール出力）を画像としてレンダリングして渡し、OCRで読ませることで**約59〜70%のエンドツーエンド課金削減**を実現したという報告がある。🔶（引用: X @digimaga「篠原修司」）画像トークンの課金がピクセルサイズ基準であることの応用で、効果はワークロード次第。

## 7. 節約テクニック④：日常のトークン大掃除

単発の設定変更より効くのが、日常的な運用の見直し。実践者の報告から共通するポイントをまとめると:

- **会話のターン数を減らす**: 複数の質問がある場合、1つずつ送るのではなく1メッセージにまとめる。会話が続くほど、それまでの全文が毎回まるごと再送されて消費されるため、ターン数を減らすだけで節約になる。🔶（公式の利用制限ベストプラクティス）
- **不要なMCP/コネクタを切る**: GmailやGoogleドライブなどのコネクタを繋いだままにすると、内部的にツール定義（例: Gmail連携だけで12個分のツール説明）が毎回読み込まれ、消費が激しくなる。Web版で設定したコネクタはClaude Codeにも引き継がれるため、`/mcp`で確認し不要なものは無効化する。🔶
- **Projects機能のキャッシュ＋RAGを活用する**: アップロードした文書はキャッシュされ、長い文書でも該当箇所だけを読むRAGの仕組みが組み込まれている。長文を毎回扱うタスクはProjects機能に資料をまとめておくと消費を抑えられる。🔶
- **オートコンパクトの閾値を下げる**: Claude Codeには会話が一定量を超えると自動要約する「オートコンパクト」があり、デフォルトの閾値は高め。閾値を下げて（例: 15万トークン）こまめに要約させると利用上限に達しにくくなる（ただし要約中は作業が止まるトレードオフがある）。🔶
- **メモリ・設定ファイルの棚卸し**: メモリの目次ファイルを圧縮する（8.4KB→約5.5KB、約35%減の実績）、完了済みツールの情報をアーカイブへ移す、自作スキルの説明文を半減させる（約600トークン/セッションの削減実績）といった「トークン大掃除」も効果がある。🔶（実践者の報告）
- **`/btw`でサイドチャットを使う**: Claude Codeの`/btw <質問>`は、会話履歴に一切残らない「サイドの質問」機能。✅（Claude Code公式ドキュメント）作業中でも割り込みで使え、本題の処理は止まらない。ただしツール呼び出しはできず、今の会話に既にある情報だけで答える点に注意。親の会話のプロンプトキャッシュを再利用するため追加コストもごくわずかで、公式には「サブエージェントの逆」——全会話が見えるがツールは使えない——と説明されている。✅

**対策：トークン切れに備える引き継ぎ書を作っておく**

週間枠やレート制限に達してFable 5が使えなくなっても作業を止めないために、枠が尽きる前に「引き継ぎ書」を1つ作らせておくとよい。現在の状態・決定事項とその理由・変更したファイル一覧・残タスク・注意点をまとめたドキュメントがあれば、Codexや別のモデル・別セッションにそのまま作業を引き継げる。

## 8. 注意点：安さだけ追うと起きること

- **safety classifierが挙動・コストに影響する**: 危険と判定されたリクエストは拒否（refusal）されるか、内部的にOpus 4.8へフォールバックされることがある。フォールバック時はプロンプトキャッシュの再課金を避けるための「fallback credit」が適用されるが、想定外の挙動として戸惑うことがある。✅
- **ZDR（ゼロデータ保持）が使えない**: Fable 5・Mythos 5は30日間のデータ保持が必須で、ZDR契約の対象外（Covered Model）。✅（公式ドキュメント）機密性の高い用途では要確認。
- **日本語やコードは実質コストがさらに上がる**: 新型トークナイザーにより同一テキストで約30%多くトークン化されるため、日本語中心の運用では体感コストが料金表の数字以上に膨らみやすい。✅🔶
- **安全側に倒すほど性能が落ちる場合がある**: セーフティ由来のブロックが働く区分（Cybersecurity・Biology等）では、公式ベンチマーク表でもFable 5とMythos 5のスコア差が大きく開く（星印付き区分）。安さや速さだけでなく、この種の制約も踏まえて選定したい。✅

## 9. 実践例

- **Stripe**: 5000万行のRubyコードベースの移行作業を、通常なら2ヶ月かかるところを1日で完了させたと公式が紹介。✅（Anthropic公式）
- **Hebbia**: 金融分析のベンチマークで最高スコアを達成。✅（Anthropic公式）
- **個人開発者のオーケストレーション実践**: Fable 5を設計・レビューの司令塔に限定し、実装をSonnet 5やCodexに委譲する運用で、4本のアプリ開発後もClaude全体の週間枠消費を31%、Fable専用枠消費を36%に抑えたという報告がある。🔶
- **大原かほ氏（UXデザイナー）の実践**: ファイル操作をネイティブツール優先にしてシェル経由を減らす、安定した情報をプロンプト前方に固定してキャッシュヒット率を87.5%まで高める、セッションログを解析して無駄なBashコマンドを可視化する、といった運用でコストを可視化・削減している。🔶

## 10. 今日からやること

1. **Effortはhigh（デフォルト）から。ルーティン作業だけmedium/lowへ**（4章）——xhigh・maxは能力が最重要な場面に限定する
2. **設計・計画はFable 5、実装は別モデルに渡す役割分担を試す**（5章）——ターミナルなら`/advisor`、デスクトップ/Webアプリならプロンプトで明示指定

## 12. まとめ

Fable 5は、最高性能である一方で最も高価なモデルでもあり、しかも安全性インシデントによる停止と復旧という異例の経緯をたどってきた。だからこそ「常に最上位モデルを使う」ではなく、Effortの使い分け、設計と実装の役割分担（バーベル戦略）、トークン圧縮ツール、日常のコネクタ・会話運用の見直し——これらを組み合わせて使う設計力が問われる。無償期間・レート制限リセットが繰り返し発表されている今のうちに、自分の運用の型を作っておきたい。
